# SkyOps Self-Hosted Platform — Customer Deployment & Operations Guide

Welcome to **SkyOps**, the Kubernetes Incident Management and FinOps platform designed to run entirely on your own infrastructure.

This guide provides end-to-end instructions for deploying the SkyOps Control Plane on an Ubuntu Server machine, creating the initial administrator account, registering your Kubernetes clusters, and deploying the SkyOps agent via Helm.

---

## 1. System Requirements

### Host Machine Requirements
- **Operating System**: Ubuntu Server 20.04 LTS, 22.04 LTS, or 24.04 LTS (x86_64 / amd64).
- **CPU**: Minimum 2 physical or virtual CPU cores (4 cores recommended for >10 clusters).
- **Memory**: Minimum 4 GB RAM (8 GB recommended for high telemetry volume).
- **Storage**: Minimum 20 GB free disk space (SSD recommended for PostgreSQL performance).
- **Network**: Outbound internet access during installation for Docker package downloads. Inbound TCP port 3000 (or 443 with reverse proxy).

### Monitored Kubernetes Cluster Requirements
- **Kubernetes Version**: v1.24 through v1.31+.
- **Package Manager**: Helm v3.8.0+.
- **Connectivity**: Monitored clusters only need outbound HTTPS access to the SkyOps Control Plane URL. No inbound ports into your Kubernetes clusters are required.

## 2. Installing SkyOps Control Plane

### Option A: One-Command Installation (Recommended)

Log in to your Ubuntu Server as a user with `sudo` privileges and run the official installer:

```bash
curl -fsSL https://get.skyops.io/install.sh | sudo bash
```

> **What the installer does automatically:**
> 1. Verifies your system meets CPU, RAM, disk, and operating system requirements.
> 2. Installs Docker Engine and Docker Compose plugin if not already present.
> 3. Creates the `/opt/skyops` deployment directory with strict permissions.
> 4. Generates cryptographically secure secrets (`JWT_SECRET`, `POSTGRES_PASSWORD`, `ENCRYPTION_KEY`).
> 5. Starts the PostgreSQL 16 database and SkyOps Control Plane containers.
> 6. Applies database schema migrations automatically.
> 7. Installs the `skyops` management CLI tool to `/usr/local/bin/skyops`.
> 8. Verifies container health and displays your dashboard URL.

### Option B: Manual Docker Compose Installation

If your organization prefers manual deployment or air-gapped workflows:

1. Clone or extract the SkyOps release bundle to `/opt/skyops`:
   ```bash
   sudo mkdir -p /opt/skyops && cd /opt/skyops
   sudo git clone https://github.com/skyops-software-solutions/skyops.git .
   ```

2. Initialize your production configuration:
   ```bash
   sudo cp .env.production.template .env
   sudo chmod 600 .env
   ```

3. Generate secure secrets and populate `.env`:
   ```bash
   sudo sed -i "s/change_me_to_a_secure_jwt_secret_min_32_chars/$(openssl rand -hex 32)/" .env
   sudo sed -i "s/change_me_to_a_secure_database_password/$(openssl rand -hex 24)/" .env
   sudo sed -i "s/change_me_to_a_secure_32_byte_hex_key/$(openssl rand -hex 32)/" .env
   ```

4. Launch the stack:
   ```bash
   sudo docker compose up -d
   ```

## 3. Initial Administrator Setup

1. Open your web browser and navigate to:
   ```
   http://YOUR_SERVER_IP:3000
   ```
   *(Or your configured domain name if you have configured DNS and a reverse proxy).*

2. The **First-Run Setup Wizard** will appear automatically:
   - Enter your **Organization Name** (e.g. *Acme Engineering*).
   - Enter your **Administrator Full Name**.
   - Enter your **Work Email** (used for login and system alerts).
   - Choose a strong password (minimum 8 characters).

3. Click **Complete Setup**. The setup endpoint permanently locks to prevent unauthorized re-registration.

---

## 4. Registering a Kubernetes Cluster

1. In the SkyOps dashboard, navigate to **Clusters** in the left sidebar.
2. Click **+ Register Cluster** in the top right.
3. Fill in the cluster registration details:
   - **Cluster Name**: Friendly display name (e.g. `production-us-east`).
   - **Environment**: Select `Production`, `Staging`, or `Development`.
   - **Distribution**: EKS, GKE, AKS, OpenShift, K3s, or Vanilla Kubernetes.
4. Click **Register Cluster**.
5. The dashboard will generate a dedicated **Agent Authentication Token** and show the ready-to-use Helm installation command.

## 5. Installing the Go Agent in Your Kubernetes Cluster

On your workstation or CI/CD runner configured with `kubectl` access to your target cluster:

### Step 1: Add the SkyOps Helm Repository
```bash
helm repo add skyops https://charts.skyops.io
helm repo update
```

### Step 2: Install the Agent Chart
Execute the command generated by the dashboard (or substitute your credentials):

```bash
helm install skyops-agent skyops/skyops-agent \
  --namespace skyops \
  --create-namespace \
  --set serverUrl="https://YOUR_SKYOPS_DOMAIN:3000" \
  --set clusterId="YOUR_CLUSTER_ID" \
  --set agentToken="YOUR_AGENT_TOKEN" \
  --set rbac.tier="operator"
```

> **RBAC Permissions Note**:
> - `rbac.tier="observer"`: Read-only access. Collects logs, resource state, and metrics. Cannot perform pod restarts or rollouts.
> - `rbac.tier="operator"` (Default): Allows workload remediation (Pod restart, Deployment rollout) following explicit human approval in the dashboard.
> - `rbac.tier="admin"`: Required only if you want the dashboard to support node cordon/uncordon operations.

### Step 3: Verify Agent Connectivity
Check the agent pod status:
```bash
kubectl get pods -n skyops -l app.kubernetes.io/name=skyops-agent
```

Within 15–30 seconds, your cluster status in the SkyOps dashboard will switch to **Healthy (Online)** with real-time node counts, pod health, and telemetry streams.

## 6. Commercial License Import (Optional)

By default, SkyOps operates in **Community Edition** (up to 3 clusters and 30 nodes with core incident management).

To activate an Enterprise or Team license:

1. In the dashboard, click **Settings** → **Commercial License** tab.
2. Click **Import License**.
3. Paste the contents of your signed license file (or upload `license.json`).
4. Click **Verify & Activate**.
5. The platform validates the cryptographic Ed25519 digital signature locally and updates your cluster/node quotas instantly without restarting.

## 7. Configuring AI Providers (Optional)

SkyOps operates completely offline with zero external network dependencies using our deterministic heuristic intelligence engine.

If you wish to augment incident analysis with LLMs:

1. In the dashboard, navigate to **Settings** → **AI & Privacy**.
2. Select your preferred provider:
   - **No AI / Deterministic Mode** (Default): Offline, zero data transmission.
   - **Google Gemini**: Enter your API key and select model (`gemini-3.8-flash`).
   - **OpenAI-Compatible**: Enter your endpoint and API key (works with OpenAI, Azure OpenAI, or LiteLLM).
   - **Local Inference Server**: Point to an on-premise Ollama or vLLM instance (e.g. `http://ollama.internal:11434/v1`).
3. Check the **Data Sharing Consent** toggle to authorize outbound analysis.
4. Click **Test Connection & Save**.

## 8. Everyday Administration & Maintenance

SkyOps installs the `skyops` CLI command for system administration:

```bash
# Check status of containers and health checks
skyops status

# View live application logs
skyops logs -f

# Create an immediate database and telemetry backup
skyops backup

# Restore from a backup archive
skyops restore /opt/skyops/backups/skyops_backup_20261106_120000.tar.gz

# Restart services
skyops restart

# Check for and apply versioned software updates
skyops update
```

## 9. Production TLS & Reverse Proxy Setup

For production deployments, we strongly recommend putting an HTTPS reverse proxy in front of SkyOps.

### Example Nginx Configuration (`/etc/nginx/sites-available/skyops`)
```nginx
server {
    listen 80;
    server_name skyops.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name skyops.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/skyops.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/skyops.yourdomain.com/privkey.pem;

    client_max_body_size 25M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Reload Nginx:
```bash
sudo nginx -t && sudo systemctl reload nginx
```
Your SkyOps self-hosted installation is now fully secured with SSL/TLS!
